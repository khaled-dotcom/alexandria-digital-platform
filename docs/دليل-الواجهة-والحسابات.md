# دليل الواجهة والحسابات — منصة الإسكندرية الرقمية

## ١. الحسابات وكلمات السر

### حسابات الموظفين — من `/login`

**الباسورد لكل الحسابات دي: `alexandria2026`**

> ⚠️ دي حسابات **تجريبية** اتعملت بـ `npm run seed`. قبل أي تشغيل حقيقي غيّرها كلها
> بـ `npm run set-password` أو من لوحة الإدارة `/admin` — الباسورد ده مكتوب في الكود
> ومعروف لأي حد شاف المشروع. الدومين `alexandria.gov.eg` توضيحي برضه.

**الدخول بيقبل اسم المستخدم أو الإيميل** — أي حساب تحته الاتنين شغّالين.

### التسلسل الوظيفي والوحات المنفصلة

كل مستوى ليه **لوحة مختلفة** بيتحوّل لها تلقائيًا بعد الدخول، ومفروضة بعزل حقيقي
على مستوى الـ API مش مجرد إخفاء في الواجهة:

| المستخدم | الاسم | الدور | اللوحة بعد الدخول | بيقدر إيه |
|---|---|---|---|---|
| `governor` | اللواء محمد الشريف | **المحافظ** | `/governor` (تنفيذية) | **قراءة فقط** — مؤشرات، ترتيب أحياء، أداء إدارات. ممنوع من أي تعديل حتى لو دوره أعلى رقميًا |
| `governorate` | مكتب المحافظة | **مكتب المحافظة** | `/dashboard` (كل الأحياء) | تشغيلي كامل: تحويل، تعليق، تغيير حالة، حذف — عبر كل الأحياء |
| `admin` | مدير النظام | admin | `/admin` (منفصلة) | إدارة حسابات الموظفين والأدوار وسجل التدقيق — **مقصورة عليه هو بس**، حتى المحافظ ومكتب المحافظة ممنوعين منها رغم مستواهم الأعلى |
| `supervisor` | م. أحمد عبد الرحمن | supervisor | `/dashboard` | كل الأحياء + التصعيدات (بدون تغيير) |
| `agent` | سارة محمود | agent | `/dashboard` | استقبال ومتابعة البلاغات |
| `cleaning` | م. خالد فؤاد | manager | `/dashboard` | إدارة النظافة |
| `lighting` | م. منى السيد | manager | `/dashboard` | إدارة الإنارة |

**ليه المحافظ ممنوع من التنفيذ رغم إن مستواه الأعلى؟** لأن الصلاحيات هنا مش تسلسل
هرمي بسيط بيورّث لفوق — فيه ٣ مسارات متوازية: الأدمن (نظام) ومكتب المحافظة
(تشغيل) والمحافظ (اطّلاع استراتيجي). الميدلوير `blockGovernor` في
[`src/auth.js`](../src/auth.js) بيتحط صراحةً على كل راوت بيغيّر بيانات
(تحويل/تعليق/حذف/تغيير حالة)، ولوحة الإدارة نفسها محمية بـ `requireSystemAdmin`
اللي بيتحقق من الدور بالظبط `admin` مش بمقارنة مستوى. مُغطّى بـ ٣٤ اختبار في
[`tests/roles-test.mjs`](../tests/roles-test.mjs).

| `montaza2` | المنتزه ثان |
| `sharq` | شرق |
| `wasat` | وسط |
| `gharb` | غرب |

**العزل متطبّق على مستوى SQL مش على مستوى الواجهة** — شرط `WHERE district = ?`
بيتحقن في كل استعلام. ولو حد جرّب يفتح بلاغ من حي تاني بيرجع **404 مش 403**،
عشان الرد نفسه ما يأكّدش إن البلاغ ده موجود أصلاً. ده مُغطّى بـ ٣٦ اختبار في
`tests/district-test.mjs`.

### إدارة الحسابات من `/admin`

الأدمن يقدر من اللوحة نفسها (من غير سطر أوامر):
- يشوف كل الحسابات (نشطة وموقوفة) مع آخر دخول وسجل تدقيق مختصر.
- ينشئ حساب جديد — الباسورد لو سيبته فاضي بيتولّد عشوائيًا وبيظهر **مرة واحدة بس**.
- يعدّل الدور/الحي/الإدارة/الإيميل.
- يوقف/يفعّل حساب — الحساب الموقوف بيفقد جلسته فورًا حتى لو عنده كوكي شغّال.
- يعيد تعيين باسورد أي حساب — القديم بيبطل فورًا.
- **ممنوع يوقف نفسه أو يغيّر دوره بنفسه** — تفادي قفل النفس بره النظام بالغلط.

### دخول المواطنين — من `/citizen-login`

مفيش باسورد — الدخول **بالرقم القومي + كود تحقق (OTP)** بيتبعت على الموبايل.

في التطوير (`SMS_PROVIDER=console`) الكود بيظهر على الشاشة وبيتملّى لوحده،
فتقدر تجرّب من غير بوابة SMS. الأرقام القومية التجريبية موجودة في `scripts/seed.js`.

## ٢. تشغيل المشروع

```bash
npm install
npm run seed        # بيانات تجريبية: بلاغات ومواطنين ومواعيد
npm start           # http://localhost:3000
```

### الاختبارات

السيرفر لازم يكون شغّال. حدود الطلبات الافتراضية بتتصدّى للاختبارات (وده مقصود)،
فشغّل السيرفر بحدود مرفوعة أول:

```bash
REPORT_RATE_MAX=500 LOGIN_RATE_MAX=500 RATE_LIMIT_MAX=5000 \
OTP_RATE_MAX=500 OTP_VERIFY_RATE_MAX=500 BOOKING_RATE_MAX=500 \
OTP_COOLDOWN_SEC=0 npm start

npm test            # ٤٥٩ اختبار
```

## ٣. الصفحات

| الصفحة | المسار | لمين |
|---|---|---|
| الرئيسية + البلاغ | `/` | الكل |
| حجز موعد | `/appointments` | المواطنين |
| الخريطة واللوحة | `/dashboard` | **موظفي المحافظة فقط** — مقفولة على المواطن والزوّار |
| اللوحة التنفيذية | `/governor` | المحافظ ومكتب المحافظة — قراءة فقط |
| إدارة النظام | `/admin` | الأدمن حصرًا |
| طابور المواعيد | `/queue` | موظفي المقار — تسجيل حضور المواطنين وإنجاز خدمتهم |
| متابعة بلاغ | `/track` | الكل |
| حسابي | `/my` | المواطنين |
| دخول المواطنين | `/citizen-login` | المواطنين |
| دخول الموظفين | `/login` | الموظفين — بيوجّه كل دور للوحته تلقائيًا |

**المواطن مايشوفش خريطة البلاغات ولا تفاصيلها.** المواطن بيتابع بلاغه بالرقم
المرجعي بس (`/track`)، ومابيقدرش يستعرض بلاغات التانيين ولا يشوفهم على خريطة.
العزل ده مفروض على مستوى الـ API مش بس إخفاء في الواجهة:

- `GET /api/complaints` (قائمة/استعراض) و`GET /api/stats/*` (التحليلات
  والخريطة والاتجاهات) كلها محتاجة تسجيل دخول موظف — بترجع `401` من غير
  كوكي جلسة صالحة.
- `GET /api/complaints/:ref` (متابعة بلاغ برقمه المرجعي) **فضلت عامة** —
  دي خدمة المواطن الأساسية، مختلفة تمامًا عن استعراض كل البلاغات.
- الصفحة الرئيسية بتعرض ٤ أرقام إجمالية بس (بلاغ مستلم، تم حلّه، التزام
  بالمواعيد، عدد الأحياء) من `GET /api/stats/public-summary` — endpoint
  عام مقصود، بيرجّع ملخّص بدون أي موقع أو تفصيل فردي.

## ٤. هوية الإسكندرية البصرية

كل صفحة ليها **معلم مختلف** من معالم المدينة. الصفحة الرئيسية وأغلب شرائط
البانر بتستخدم **صور حقيقية** من Wikimedia Commons (برخص CC-BY/CC-BY-SA،
الاعتماد كامل في [`/credits`](http://localhost:3000/credits)) محمّلة محليًا
في `public/img/landmarks/` — لازم تكون محلية عشان الـ CSP بيمنع مصادر صور
خارجية. الموج والطيور والنجوم والشمس فضلوا SVG/CSS مرسومة بالإيد كلمسة حركة
فوق الصورة.

| الصفحة | المعلم | صورة حقيقية؟ |
|---|---|---|
| `/` | الهيرو: كورنيش الإسكندرية | ✅ |
| `/dashboard` | كوبري ستانلي | ✅ |
| `/appointments`، `/queue` | مكتبة الإسكندرية | ✅ |
| `/my` | قصر المنتزه | ✅ |
| `/citizen-login`، `/governor` | قلعة قايتباي | ✅ |
| `/login`، `/admin` | عمود السواري | ✅ |
| `/404` | المسرح الروماني — كوم الدكة | ✅ |
| `/track` | فنار فاروس | ❌ رسمة مرسومة عن قصد — الفنار الأصلي مش موجود من قرون فمفيش صورة حقيقية أمينة له |

**ليه فاروس رسمة مش صورة؟** كل المعالم التانية موجودة فعليًا وليها صور حقيقية.
فنار فاروس مش موجود من زمان، فأي "صورة" ليه هتبقى تخيّلية أو لمكان تاني —
سيبناه رسمة واضح إنها تخيّلية بدل ما نحط صورة بديلة توهم إنها حقيقية.

المعالم المرسومة متعرّفة في [`public/js/marks.js`](../public/js/marks.js)
كـ `PARTS`، وكل واحد مرسوم في صندوق `360×170` قاعدته عند `y=170`. الأفق الكامل بيركّبهم مع بعض
بـ `translate(x, 200 − 170·s) scale(s)` عشان كل القواعد تقع على نفس خط الأرض.

**لإضافة معلم جديد:** زوّد مدخل في `PARTS` (نفس الصندوق والقاعدة)، وحطّ اسمه
العربي في `LANDMARK_NAMES` جوّه [`public/js/ui.js`](../public/js/ui.js)، وبعدين
حطّ `<div class="page-banner hero-sea" data-landmark="اسمه" aria-hidden="true"></div>`
تحت الهيدر في الصفحة اللي عايزها.

### الحركة

- **الموج** — ٣ طبقات بسرعات مختلفة (٢١ · ٣٠ · ٤٤ ثانية). كل طبقة عرضها ٢٠٠٪
  وجوّاها بلاطتين متطابقتين، والحركة بتزحزحها ٥٠٪ = بلاطة كاملة، فالتكرار
  مايبانش فيه قطع.
- **شعاع الفنار** — بيلف ذهابًا وإيابًا ٢٢ درجة كل ٤.٥ ثانية.
- **النوارس** — ٥ نوارس بمواقع وسرعات عشوائية بتعدّي عرض الشاشة.
- **النجوم** — بتظهر في الوضع الداكن بس.
- **الشمس** — نبض خفيف كل ٦ ثواني.

كل ده بيتوقف تمامًا مع `prefers-reduced-motion: reduce`.

## ٥. نظام التصميم

### الملفات

| الملف | مسؤول عن |
|---|---|
| `public/css/tokens.css` | المتغيّرات: ألوان · مسافات · خطوط · ظلال · حركة · الثيمات |
| `public/css/styles.css` | المكوّنات (٤٠ قسم مرقّم) |
| `public/css/alexandria.css` | المشاهد البحرية والمعالم والرسومات |
| `public/js/ui.js` | الثيم · التوست · لوحة الأوامر · الهيدر · معلم الصفحة |
| `public/js/marks.js` | كل رسومات المدينة |

### الألوان

ثلاث سلاسل أساسية، كل واحدة ١٠ درجات:

- **`--alx-*`** أزرق الإسكندرية (البحر العميق) — اللون الأساسي
- **`--teal-*`** تركواز المتوسط — اللون المساعد
- **`--gold-*`** ذهب الغروب — التمييز والدعوة للفعل

ودلالية: `--success` · `--danger` · `--warning` · `--info` وكل واحدة ليها
`-soft` (خلفية) و`-text` (نص مقروء عليها).

**متستخدمش قيمة لون مباشرة في المكوّنات** — استخدم التوكن الدلالي
(`var(--primary)` مش `var(--alx-600)`) عشان الوضع الداكن يشتغل لوحده.

### المسافات

وحدة الأساس ٤px: `--s-1` = 4px لحد `--s-32` = 128px.
مقاس الخط `--t-xs` (12px) لحد `--t-6xl` (60px).

### الثيم

ثلاث حالات: **تلقائي** (يتبع النظام) → **فاتح** → **داكن**، بتتبدّل من زرار
الهيدر أو `Ctrl+K`. الاختيار بيتحفظ في `localStorage` وبيتطبّق من
`public/js/theme-boot.js` — سكربت عادي (مش module) في الـ `<head>` عشان
يشتغل قبل أول رسم فمايحصلش وميض.

### اختصارات الكيبورد

| الاختصار | بيعمل إيه |
|---|---|
| `Ctrl/Cmd + K` | لوحة الأوامر — بحث في كل الصفحات |
| `↑ ↓` | تنقّل في نتائج اللوحة |
| `Enter` | تنفيذ |
| `Esc` | إغلاق |
| `Tab` من أول الصفحة | رابط «تخطَّ إلى المحتوى» |

## ٦. قرارات معمارية

**ليه مفيش React/Next.js؟** الموقع HTML/CSS/JS عادي من غير خطوة بناء. تعديل ملف
= refresh وخلاص. ده مقصود عشان:
- أي مطوّر في المحافظة يقدر يصلّح حاجة من غير ما يتعلّم stack كامل
- مفيش `node_modules` بمئات الميجات ولا build pipeline يتعطّل
- التحميل أسرع: مفيش bundle ولا hydration

**ليه الرسومات SVG مكتوبة بالإيد؟** الـ CSP بيمنع أي مصدر خارجي
(`default-src 'self'`)، فمفيش CDN ولا Google Fonts ولا صور من برّه. الخط Cairo
نفسه محمّل محليًا في `public/fonts/`. الرسومات vector بتتلوّن من متغيّرات الـ CSS،
فبتشتغل في الوضع الفاتح والداكن من غير نسخة تانية.

**ليه `node:sqlite`؟** مدمجة في Node 22.5+ — يعني صفر مكتبات native وصفر
مشاكل تنصيب على سيرفرات ويندوز.

## ٧. اللي لسه ناقص

الحاجات دي **مش موجودة**، والواجهة مافيهاش شاشات ليها عن قصد — عشان مايبقاش
فيه واجهات فاضية بتوحي بحاجة مش شغّالة:

- **التحقق من الرقم القومي** — الصيغة والتاريخ بيتفحصوا، لكن مفيش تحقق من
  السجل المدني. محتاج ربط رسمي.
- **بوابة SMS** — الكود بيتبعت عبر `providers.http`، محتاج تعاقد مع مشغّل.
- **المدفوعات والمحفظة والمترو والدخول بالبصمة** — مفيش باك إند ليها أصلاً.
- **الربط بالخط الموحّد ١٦٥٢٨** — مستني المواصفة من الجهة.
- **إحداثيات مقار الأحياء وساعات المهل** — دلوقتي تقديرات، محتاجة اعتماد رسمي.
